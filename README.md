# SMS Guard — единый интерфейс результата (прототип заданий 1–7)

## Что меняется
В веб-форме появляется **общий для всех языков итог**: «Требует внимания» либо «Явных тревожных признаков не найдено». Отображаются предполагаемый язык и количество сработавших групп из шести.

- Для английского дополнительно выводится **ML-вероятность спама** (Logistic Regression, ваша сохранённая модель).
- Для русского и казахского выводится **число сработавших групп правил**, но не выдуманная вероятность. Предупреждение о ненадёжности ML-оценки сохраняется.
- Для RU/KK распознавание языка эвристическое: наличие уникальных казахских букв указывает на казахский; иначе кириллица помечается как русский. Показатель языка может ошибаться, особенно в смешанном тексте.
- Это **не Risk Score**, который в ТЗ реализуется только в задании №13 с URL-моделью и калибровкой.

## Установка
1. Убедитесь, что уже установлены файлы предыдущего патча: `ml/cyrillic_rules.py` и `ml/rules.py`.
2. Сделайте копии `apps/analysis/views.py` и `templates/check_sms.html`.
3. Скопируйте файлы этого архива в **корень** существующего проекта `sms_guard` с сохранением относительных путей, подтвердив замену двух файлов. Новый тест добавится в `tests/`.
4. Из PowerShell в корне проекта выполните:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe manage.py runserver
```

5. Проверьте интерфейс `http://127.0.0.1:8000/check/sms/` на примерах:
   - `Your order has been shipped.` — ML-вероятность и единый итог.
   - `Привет! Встречаемся завтра в 18:00.` — единый итог; 0/6 групп; без ML-вероятности.
   - `Сәлем! Ертең сағат 10:00-де кездесеміз бе?` — единый итог; 0/6 групп; без ML-вероятности.
   - `Срочно переведите деньги и сообщите код подтверждения!` — предупреждение и обнаруженные признаки; без ML-вероятности.

## Что требует само ТЗ
В разделе 2.2 указано, что для RU/KK без размеченного обучающего и отдельного тестового набора корректнее использовать правила и проверку ссылок с предупреждением о ненадёжности ML. Единый числовой Risk Score 0–100 с коэффициентами и URL-моделью относится к **заданию №13**, а не к заданиям 1–7.
